# AI KHEMRA BRO v7.00 — Python and CSS stability audit

**Audit scope.** The current application was reviewed for Python correctness, Streamlit rerun/state behavior, Settings isolation, mobile CSS safety, audio-processing reliability, dependency alignment, and regression coverage. The audit did not add user-facing features.

## Result

The production workflow is structurally healthy after the latest Settings fixes. The main stability issue discovered in source review was an overridden duplicate `video_to_srt` function: a legacy implementation appeared first in the file, then a newer multilingual implementation replaced it later. Python always used the second definition, but retaining the first one made future maintenance risky because developers could modify the inactive implementation by mistake. The obsolete definition was removed, leaving one active subtitle-generation pipeline.

The live audio integration test also showed that a four-request Edge TTS burst could intermittently fail at the external provider even though individual voice tests passed. The production request limit was reduced from four parallel requests to two. This preserves all four locked voice roles while trading a small amount of peak speed for materially better provider reliability. The integration test profiles were also aligned with the active production M, F, M_THINK, and F_THINK profiles so the test now validates exactly the voices delivered by the app.

## Measured integration result

The real four-role overlap mix was generated as stereo MP3 with a duration of **8.328 seconds** and a size of **200,493 bytes**. The faster-whisper base model loaded in **2.861 seconds** and transcribed a Khmer Edge TTS reference clip in **0.844 seconds** for a real-time factor of **0.19**. Edge TTS latency was much slower during this external-provider run—about 81 seconds for each short reference clip—which reinforces the decision to use bounded concurrency and existing retries rather than increasing parallel calls.

## No additional user-facing feature is required now

The application already has the requested core capabilities: authenticated access, Khmer dashboard labels, multilingual targets, four locked voices, subtitle translation, video-to-SRT processing, SRT-to-speech rendering, and the simplified Settings control. Adding more visible controls now would increase UI complexity and risk undermining the recent mobile and Settings stability work.

## Recommended maintenance only

The safest next maintenance step is to keep the new source audit and regression suite in the repository and run them before every deployment. Keep the current dependency pins in `requirements.txt`; the local audit environment required installing the pinned `faster-whisper==1.2.1` package before the end-to-end audio integration test could run. No production code change is needed for this environment-only setup detail because Streamlit Cloud installs the pinned requirements during deployment.
